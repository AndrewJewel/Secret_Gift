# 2026-08-07 — Rediseño completo de Santa Secreto → Regalo Secreto

Sesión larga: pasó de ser una app de un solo grupo con un PIN fijo en el
código, a un sistema multi-grupo con cuentas, y de Material básico a un
diseño Glassmorphism completo. Quedó publicada en
https://santa-secreto-860c3.web.app — pendiente resolver la instalación
del APK en Android.

## Lo que se hizo hoy

### 1. Auditoría de seguridad y arreglo del diseño original
- Se detectó: PIN maestro `"7733"` fijo en el código fuente (visible en
  cualquier build), sin reglas de Firestore (cualquiera podía leer/escribir
  todo directo desde la consola del navegador), PINes de participantes en
  texto plano y expuestos en la lista pública, deseos de regalo visibles
  para todos en vez de solo para quien regala.
- Se corrigió con reglas de Firestore que bloquean toda escritura directa
  desde el cliente y todo acceso a subcolecciones `privado/`.

### 2. Rediseño a multi-grupo
- Antes: una sola colección `participantes` global, un solo PIN maestro.
- Ahora: `grupos/{codigo}` (código corto tipo `AZUL-7F3K`, generado al
  crear el grupo) con su propia ocasión, nombre, valor mínimo, y PIN
  maestro propio elegido por quien lo crea.
- El PIN maestro del grupo sirve para el sorteo y (con el mismo PIN o el
  propio del participante) para borrar entradas — pero **nunca** para ver
  el amigo secreto de otra persona (eso solo con el PIN propio).
- Nueva Cloud Function `editarParticipante`: el PIN maestro puede corregir
  el nombre de un participante (typos), no solo borrarlo.

### 3. Cuentas (nickname + contraseña) — "login suave"
- Sistema aparte del PIN de grupo (conviven los dos, no se reemplazan).
- Nickname único (verificado server-side), contraseña con mínimo 8
  caracteres + mayúscula + minúscula + número + carácter especial,
  hasheada con bcrypt en la Cloud Function (nunca en texto plano).
- Al crear/unirse a un grupo estando con sesión activa, el grupo queda
  vinculado a la cuenta automáticamente → pantalla "Mis grupos" para
  encontrarlos desde cualquier dispositivo.

### 4. Compartir grupo
- Botón de compartir (selector nativo, WhatsApp incluido) y botón de
  código QR, ambos junto al código dentro de la pantalla del grupo (no
  solo al crearlo — quedan disponibles siempre).
- El QR/link codifica `https://.../?codigo=XXXX`: al abrirlo, la app salta
  directo a la pantalla de registro de ese grupo sin pedir escribir nada.

### 5. Bugs grandes que aparecieron y se resolvieron
- **Deploy que no se activaba**: `firebase deploy` reportaba éxito pero el
  sitio seguía sirviendo una versión vieja — el paso de "release" nunca se
  completaba por un error posterior (política de limpieza de imágenes) que
  abortaba todo el proceso. Se resolvió esa política aparte y confirmando
  siempre `Deploy complete!` en el log, no solo "file upload complete".
- **"Spinning infinito" al abrir la app**: la pantalla de inicio esperaba
  (sin límite de tiempo) una respuesta de `shared_preferences` antes de
  mostrarse. Rediseñado: la pantalla de inicio ahora se muestra siempre de
  inmediato, todo lo demás carga en segundo plano sin bloquear nada.
- **`MissingPluginException` de shared_preferences en web**: el archivo
  interno de Flutter que registra los plugins para web
  (`web_plugin_registrant.dart`) se quedó desactualizado y nunca se
  regeneró en builds sucesivos. Se resolvió con `flutter clean` completo.
- **Bug de Firebase (`cloud_functions` package) en producción web**:
  cualquier llamada a una Cloud Function tronaba con "Int64 accessor not
  supported by dart2js" — bug conocido y sin arreglar del plugin oficial
  (flutterfire#17924). Se dejó de usar el paquete `cloud_functions` y se
  llama a las funciones directo por HTTP (`lib/funciones.dart`).
- **Etiquetas de campos de texto cortadas a la mitad**: bug conocido de
  Flutter al combinar `BackdropFilter` (vidrio) con la etiqueta flotante
  estándar. Se evitó por diseño: etiqueta fija arriba del campo, nunca
  flotante.

### 6. Rediseño visual — Glassmorphism
- Todas las pantallas (8): fondo blanco como color principal, tarjetas de
  vidrio esmerilado (blur + translucidez) teñidas del color de la ocasión
  (azul real para Amigo Secreto, rojo para Santa Secreto), textos oscuros
  sobre el vidrio claro.
- Tipografía Fredoka (títulos) + Nunito (cuerpo).
- Texto de la pantalla de inicio cambiado a "Gestión de Grupos".
- Nombre de la app cambiado de "Regalo Sorpresa" a **"Regalo Secreto"** en
  todo el código: título de la app, pestaña del navegador, manifest.json,
  label del APK Android, descripción en pubspec.yaml.
  - Pendiente manual (no se puede por CLI sin login interactivo): renombrar
    el nombre visible del proyecto en la consola de Firebase (el ID
    `santa-secreto-860c3` sí es permanente, no se puede cambiar).

### 7. APK para Android
- Se encontró y corrigió un bug real de compilación: `android/app/build.gradle.kts`
  no tenía `signingConfig` en el build de `release` → generaba un APK sin
  firmar (`apksigner verify` fallaba con "Missing META-INF/MANIFEST.MF").
  Se agregó `signingConfig = signingConfigs.getByName("debug")`.
- El APK se sube automáticamente a `web/descargas/regalo-secreto.apk` en
  cada build y queda descargable en
  `https://santa-secreto-860c3.web.app/descargas/regalo-secreto.apk`
  (para instalar directo desde el navegador del celular, sin pasar por PC).

   `C:\Users\andre\AppData\Local\Android\Sdk\platform-tools`. Falta que el
   usuario active "Depuración USB" en Opciones de desarrollador y conecte
   el celular por cable.

   borrar participantes uno por uno, no el grupo entero. Debe poder
